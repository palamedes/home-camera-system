Automations

When something happens, do something.

Driving Sentry from outside Every automation has a URL — for a wall switch, a phone shortcut, or another machine

Every automation can be run by fetching its URL with the shared token, whether or not it also has a trigger. Anything that can make an HTTP request can drive the house: a Shelly's own input button, an iOS or Android shortcut, a scene controller, a cron job on another machine.

The URL

/api/hook/run/<name>?token=…

The token is shared by every hook endpoint and is shown on each automation below. Treat it as a password: anyone on your network who has it can run anything listed here.

Both methods work

  • GET or POST — whichever your caller finds easier.
  • The token can go in the query string, or in an X-Sentry-Token header if putting secrets in URLs bothers you (it should — query strings end up in logs).

What it answers

{"ok": true, "ran": 2, "errors": []} — and ok is false with the failures listed if part of it did not work, rather than reporting success for a half-run scene.
